# NAKA Title Designer Pro 要件定義（v0.1 / 2026-11-01）

## 前提
- 対象: Adobe Premiere Pro 2026 (26.x) 以降 / Windows 限定 / 個人利用（ライセンス認証なし）
- 名前: プラグイン名・ベンダー・カテゴリは NAKA / `NAKAfx_` / `NAKAfx`

## 組み込み方式
- C++ カスタムインポーター（Premiere Pro C++ SDK 26.0、`SDK_Custom_Import` 方式）
  - 拡張子 `.tdp`、メニュー「ファイル > 新規」から作成
  - クリップのダブルクリックで設定ダイアログ（= デザイナー exe）を起動
  - フレームはインポーターがその都度ネイティブ描画（PNG・連番は使わない）
- デザイナーは別プロセス（exe）。インポーターは終了を待つ（モーダル）
  - 終了コード 0 = 保存、1 = キャンセル
  - 背景用に、タイムラインの現在フレームを `getPreviewFrameEx` で取得して渡す
- 描画エンジンはインポーターとデザイナーで共有（見た目のズレ防止）
- 将来: UXP パネルから「新規 → 再生ヘッド位置に配置」

## Phase 1 の設計判断（2026-11-01 決定）
- デザイナー UI は WebView2（HTML のパネル）+ C++ の GPU 描画キャンバス。メモリを使いすぎるようなら見直す
  - SDK: NuGet `Microsoft.Web.WebView2` 1.0.4314.35（`third_party/webview2`）
- 装飾スタックのシャドウは「リストでシャドウより上にある層すべてを合成した形」の影を落とす
- 描画は Direct2D（D3D11 上の GPU）で、外部ライブラリは使わない
- `.tdp` は JSON に移行（v2）。v1（key=value）も読めるようにする

## データ保存
- 既定: `.tdp` ファイルとしてディスクに保存
  - Phase 0: `ドキュメント\NAKA Title Designer Pro\Titles\`
  - 将来: プロジェクトフォルダ配下（命名ルールは未確定）
- 同じ `.tdp` を参照するクリップは連動する。「別物として複製」機能で対処

## 機能（Phase 1 以降）
- 装飾スタック（塗り・フチ・影・光彩…）を自由な順番で重ね、並べ替えできる
- 塗りの種類: 単色 / 無段階グラデーション（線形・放射、複数ストップ）/ パターン（ストライプ・ドット）。フチにも同じ塗りを使える
- フチ: 太さ、結合（マイター / ラウンド / ベベル）、マイター上限
- 内側・外側シャドウ、背景（座布団）、疑似立体ロングシャドウ
- カーニング（ペアごとの手動調整を含む）、トラッキング、行間
- 文字ごとのスタイル（色・サイズ・フォント）
- プリセット（装飾スタック / アニメーション / テロップ全体）
- 文字単位アニメーション（範囲セレクター方式、イン / アウトはクリップの頭と尻が基準）
- 3D: 押し出し、ベベル、光沢（PBR）
- 縦書き・ルビ: 横書きの実装が安定したら対応

## 段階
| Phase | 内容 |
|---|---|

| 1 | 2D 静止テロップ一式 + プリセット |

## Phase 0 の合格条件
1. 「ファイル > 新規」にメニューが出て、デザイナーが起動する
2. 保存すると `.tdp` がプロジェクトに入り、タイムラインに置ける
3. タイムラインのクリップをダブルクリックするとデザイナーが開き、保存で Premiere の表示が変わる
4. デザイナーの背景にタイムラインの現在フレームが出る
5. 描画は GPU（D3D11 + Direct2D）で行い、アルファ付きで正しく合成される（上下反転・色ずれがない）
6. 時間に応じた描画（フェードイン）がフレームごとに正しく出る
7. スクリプト（ExtendScript / UXP）から `.tdp` を読み込んで、タイムラインに配置できる

## Phase 2 の設計（2026-11-01 決定）
- 方式: プリセット＋調整（ユーザー決定）。キーフレーム編集は作らない
- 動き: フェード、タイプライター、ポップ、ズーム、落下・バウンド、飛び出し、スライド、回転。登場と退場の両方
- 調整: 単位（1文字／1行／全体）、順番（先頭・末尾・中央から・両端から・ランダム）、1つの長さ、次の文字までの間隔、遅れ、量、方向、カーブ、一緒にフェード
- 退場は「登場の逆再生」。ただし落下は下へ落ちる。退場は `.tdp` の長さ（durationFrames）の最後で終わる。Premiere でクリップの終わりを切ると退場も切れる（インポーターはトリム位置を知れないため）
- 描画: 文字（クラスタ）ごとにアウトラインを分け、変形は文字の中心を基準に適用。塗り・フチは文字と一緒に動く（グラデーションも文字に付いて動く）。不透明度の違う文字は、装飾スタック一式を別々に描いて重ねる（薄い文字ほど下）。座布団は「全体まとめて」の動きだけに付いて動く
- `fadeInFrames`（Phase 0 / 1 の仮フェード）は読み込み時に「フェード・全体」の登場に変換
- 2026-11-01: アニメーションを Premiere 実機でユーザーが確認して問題なし（クリップの長さ変更時の挙動は個別の報告なし）

- 縦書き: テキストごとに「組み方向 横書き／縦書き」。列は右から左、和文は正立、欧文は横倒し（DirectWrite の既定の縦組み）。縦書きでは「行揃え」が上／中央／下（列の中での揃えと縦の基準）、「基準（横）」が右／中／左。文字ごとのアニメーション・座布団もそのまま使える。`tdp_render_test` とデザイナー単体で確認済み。2026-11-01 Premiere 実機（スタートメニューから起動）でユーザー確認済み
  - 縦中横（2026-11-01）: 縦書きのとき、半角数字が n 桁まで続く部分（既定 2 桁、「しない」/1〜4 桁）と「!!」「!?」「?!」「??」を自動で横に並べる。ほかの範囲は「文字ごとの設定」の「縦中横」で指定。縦組みの中ではちょうど 1 文字分を占め、1 文字分より広いときは横方向だけ縮める。アニメーションでは 1 文字として動く。範囲の先頭の文字のフォント・サイズ・色を使う。「一緒に並べる記号」（入力式、既定 `()`）に入れた記号は、自動の数字の前後に付いていれば一緒に横に並ぶ（`(15)`、`[3]`、`50%` など。2026-11-01 ユーザー要望）。`tests/samples/tcy.tdp` とデザイナー単体で確認済み。2026-11-01 Premiere 実機でユーザー確認済み（記号の入力欄を含む）
  - 未対応: 約物の細かな位置調整
- ルビ（2026-11-01）: テキスト欄で親文字を選び、「文字ごとの設定」の「ルビ」に入力。続いた同じルビの文字が 1 グループで、ルビはその中央に置く（横書きは上、縦書きは右に縦書きで）。テキストごとに「ルビの大きさ」（親文字の %、既定 50）と「ルビの間隔」（px）。フチがある場合はフチの太さ分だけ離す。装飾スタックは本文と共通、色は親文字の先頭の文字の設定。アニメーションでは親文字の先頭の文字と一緒に動く。打ち足した文字には隣のルビ・縦中横を引き継がない。`tests/samples/ruby.tdp` とデザイナー単体で確認済み、Premiere 実機は未確認
  - 2026-11-01 Premiere 実機でユーザー確認済み
- グラデーション・模様の範囲（2026-11-01 ユーザー要望）: 既定で 1 行ごと（縦書きは 1 列ごと）。「フォント」の「グラデーション・模様を1行ごとに」を外すと従来どおりテキスト全体で 1 つ。ルビは範囲の計算に含めず、親文字の行の範囲で塗る。`tests/samples/gradient_lines.tdp` とデザイナー単体で確認済み。2026-11-01 Premiere 実機でユーザー確認済み
- 2026-11-01: Phase 2（文字単位アニメーション・縦書き・縦中横・ルビ）の全項目を Premiere 実機でユーザーが確認。Phase 2 完了
  - 簡易化: ルビが親文字より長くても親文字の字間は広げない（はみ出す）。複数行では行の高さを広げないとルビが上の行に重なることがある。選択枠（クリックで選べる範囲）にルビは含まない

## Phase 3 の設計（2026-11-01 決定）
- 方式（ユーザー決定）: 本物の 3D メッシュ。文字アウトライン（`ID2D1Geometry`）から押し出し・ベベルの立体を CPU で作り、D3D11（深度バッファ・MSAA）で描く。シェーダーは Windows SDK の `fxc` でビルド時にコンパイルして埋め込む。外部ライブラリは使わない
- 2D の装飾スタックとの重ね方（ユーザー決定）: スタックに「3D」層を追加する
  - 3D 層より上にある層（塗り・フチ）を合わせた形（外側・中央フチの太さを含む輪郭）を押し出す
  - 正面: 上の層の 2D の描画結果をそのまま貼る（ライトは当てない。「正面のライティング」はユーザーが選ばなかった）。正面は不透明になる
  - ベベル: 正面と同じ 2D の色に、ライトと材質で陰影・光沢を付ける
  - 側面: 前→奥の 2 色グラデーション。ライトと材質で陰影・光沢。裏面は平ら（ベベルなし）で奥の色
  - 3D 層より下にある層（シャドウ・ロングシャドウ・座布団）は、3D の描画結果に対してかかる（シャドウは立体の形の影になる）
  - 3D 層は 1 テキストにつき 1 つだけ有効（2 つ目以降は無視）
- 回転・パース（ユーザー決定: 全体＋文字ごと）
  - 3D 層に「向き（X・Y 回転）」と「パース」。消失点は画面中央。Z 回転は今までの「回転」
  - 文字ごとの 3D 回転は、アニメーションの新しい動き「3D 回転」（方向 左右 = 縦軸まわり、上下 = 横軸まわり、量 = 角度、既定 90°）。回転の中心は文字の中心・押し出しの厚みの中央
  - 3D 層が無いテキストで「3D 回転」を使うと、横（または縦）に縮める疑似表現になる
- 見た目の要素（ユーザー決定）: 押し出し（深さ、側面の色 2 色）、ベベル（なし／平ら／丸み／くぼみ、幅、高さ）、ライト（来る方向、高さ、強さ、環境光）、材質（金属っぽさ、粗さ）。映り込みはスタジオ風の簡易な環境（上が明るいグラデーション＋ライトの方向のハイライト）
- 簡易化（初回）
  - 座布団など 3D 層より下の層は、立体を回転させても平面のまま
  - デザイナーの選択枠は 2D の配置のまま（3D の回転を反映しない）
  - 文字ごとの 3D 回転では、隣の文字と重なっている部分の色が正面に混じることがある
  - ベベルの幅が文字の線の太さの半分を超えると形が崩れる
- 実装（2026-11-01）: 層の種類 `extrude`、アニメの動き `flip3d`。シェーダーは `src/common/tdp_3d.hlsl`。静止状態のメッシュは形に関わる設定ごとにキャッシュし（向き・ライト・材質・色・位置・アニメは毎フレーム適用）、HD で 3 テキストが約 7 ms/フレーム（キャッシュが無い最初の 1 フレームは約 80 ms）。MSAA（8x まで）、描画先は文字の範囲だけ
  - `tests/samples/extrude.tdp`（金属・フチ＋平らベベル＋パース・くぼみ＋3D 回転）と、縦書き・ルビ・縦中横のサンプルに 3D 層を足したもの、3D 層なしの 3D 回転を `tdp_render_test` で確認済み。デザイナー単体で 3D 層の追加・編集・3D 回転の選択・保存（終了コード 0）・保存内容の再描画を確認済み
  - 2026-11-01 `C:\ProgramData\NAKA\TitleDesignerPro\` に配置（ハッシュ一致、ローダーは変更なし）。2026-11-02 Premiere 実機でユーザー確認して問題なし
- 2026-11-02 ユーザー要望: (1) 3D で塗りの部分だけにベベルを付けたい、2D でもベベルを使いたい (2) 今の質感に加えて、写真のようなリアルな金属の質感（金・銀・クロームなど、強い映り込み）も使いたい

### 層ごとの質感（ベベル・材質）の設計（2026-11-02 決定）
- ベベル（ユーザー決定: 層ごと）: 塗り・フチの層ごとに「ベベル」（なし／平ら／丸み／くぼみ、幅、高さ）。その層の形の縁からの距離（GPU で距離場を作る）で高さを決め、画素ごとに陰影を付ける。2D でも 3D の正面でも同じ見た目（3D の正面は上の層の描画結果を貼るため）。3D で回しても正面の段差は陰影の表現で、輪郭は切り込まない
  - 例: フチは平らなまま、塗りだけ丸みベベル。外側フチにベベルを付けると、フチの外周に縁が付く
- 材質（ユーザー決定: 層ごと）: 塗り・フチの層ごとに「材質」。「なし」は今までどおり 2D の色（ベベルがあるときは陰影だけ足す）。「あり」は層の色・グラデーションを素の色にして、ライトと映り込みで描く（金属っぽさ・粗さ・ヘアライン）
  - プリセット（UI）: 光沢、金、銀、クローム、銅、ヘアライン。選ぶと材質の値と層の色（単色）を書き換える
- 映り込み（ユーザー決定: 内蔵）: 計算で作る環境。「やわらか」（今までの 3D の映り込み、既定）と「スタジオ」（天井の大きなライト、左右の縦長ライト、明るい地平線、暗い床で強い明暗。金属向け）。外部の画像は使わない
- ライトはテキストごと（「ライトと映り込み」）: 来る方向、高さ、強さ、環境光、映り込みの種類。3D 層と、材質・ベベルを使う塗り・フチで共通。Phase 3 初版で 3D 層に持っていたライトの値は、読み込み時にテキストのライトへ移す
- 3D 層の側面にも材質プリセット（UI で側面の色・金属っぽさ・粗さを書き換える）
- 実装（2026-11-02）: `src/common/tdp_surface.hlsl`（シード → ジャンプフラッド → 高さ → 縦横のぼかし → Sobel 法線で陰影）、照明は `tdp_light.hlsli` を 3D と共用。塗り・フチの層を描いたあと、材質「あり」かベベルがある層だけこのパスを通す。保存形式: 層に `material`（none/lit）・`metallic`・`roughness`・`brushed`・`bevel`・`bevelWidth`・`bevelHeight`、テキストに `light`（angle・height・intensity・ambient・env soft/studio）
- 確認（2026-11-02）: `tests/samples/surface.tdp`（金＋銀フチの 3D、2D ベベルのみ、ヘアライン銀、銅、クローム）を `tdp_render_test` で描画して見た目を確認、HD で約 7 ms/フレーム。デザイナー単体で、塗りの「質感」（金プリセット → 映り込みがスタジオに切り替わる）、3D 層の側面プリセット、「ライトと映り込み」の変更、保存（保存ファイルの再描画）を確認。Premiere 実機は未確認
- 2026-11-02 ユーザー指摘で修正: (1) 3D の正面（塗り・フチの材質）が光の方向や 3D の向きでほとんど変わらなかった → 映り込みの環境を光の方向に合わせて回す（既定の 225° では従来と同じ）、3D 層より前の層は 3D 層の回転（rotX・rotY）で法線を回して陰影を付ける。文字ごとの 3D 回転（flip3d）は正面の陰影に反映しない（近似） (2) ベベル・材質のボタンを押しても幅・高さ等の項目が出なかった → パネルを作り直すように修正

### 実使用での課題への対応（2026-11-02）

- **カーニング**（要望: 自動カーニング＋AE のように文字の間を選んで矢印キー）
